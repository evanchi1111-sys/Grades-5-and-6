# P1：管理中心正式化與試點（六年級數學）

## 已確認的決策
1. 第一階段用「靜態 JSON＋本機管理中心」，第二階段再上 Supabase。
2. 試點選**六年級數學**（單元一：最大公因數與最小公倍數）。
3. 教材與考卷**僅自家使用**（本專案不對外散布；上傳到雲端或 AI 前仍會先詢問）。
4. 審核採**自我審查**（作者可兼任審核者），不分級。
5. 代碼照 `G?-科目-U??`。

## 這次做了什麼
- **Schema 擴充**：題型加入 `order`（排序）、`sort`（分類），讓既有題庫 6 種題型都能完整容納；題目可帶 `table`、`answerAnyOrder`；版本加入 `selfReview`。
- **既有題庫轉入（唯讀）**：`content-manager/bank-adapter.js` 讀取 `index.html` 的題庫（執行同一行取得題目資料，原檔不動），題目 id 用原系統相同的雜湊寫入 `legacyRef`，之後可一對一對應。
- **管理中心**：新增題庫轉入卡片、題目／段落／知識點編輯器（含新增、刪除；只限草稿與待審核）、備份與還原、自我審查設定。
- **試點單元**：`G6-MAT-U01`（29 題、4 個知識點、來源檔含題庫與兩份 PDF 的雜湊）。

## 測試結果
| 項目 | 結果 |
|---|---|
| 全題庫壓力測試 | **43 個單元、1,479 題全部轉入**，題數與原題庫逐單元相同（選擇 865、是非 278、填充 172、配合 65、分類 53、排序 46）；Schema 與語意 0 錯誤、0 行無法解析 |
| 試點單元 | G6-MAT-U01：29 題（選擇 18、是非 5、填充 5、排序 1），Schema 0 錯誤；題目逐一帶 legacyRef |
| 編輯器 | 修改題目後 `revision` 增加、狀態回到待審核；新增與刪除題目正常 |
| 自我審查 | 作者＝審核者可核准，版本紀錄標示 `selfReview: true`；關閉設定後被擋，換人審核則通過 |
| 發布包 | manifest 與單元檔通過 Schema；單元檔 19 KB |
| 備份與還原 | 備份→清除→還原，內容逐位元相同；格式錯誤的備份被拒絕 |
| 學生端資料 | 管理中心只寫入 `adv-cm-v1`，其他 key 不動 |

## 要注意的地方
- 試點資料**來自既有題庫**，不是全新上傳的教材；還沒有真正走過「上傳 PDF → 解析 → 審核」（PDF／AI 解析仍未接）。
- 已核准的題目有「沒有來源頁碼」提醒（29 項），因為既有題庫本來就沒記頁碼；這是提醒，不阻擋發布。
- 試點單元沒有教材段落（六年級數學目前沒有學習島頁面），學生端要等 P2 的 Content Loader 才會看到。
