# Phase C：教材架構驗證報告

目的：用第二個「不同類型」的單元（六年級 第 1 單元 熱的影響與傳播）驗證 Phase B 的架構是否可重用，並找出寫死的部分。

## 結論
資料結構（單元資料、題目、標籤、實驗、示範、成就）可以重用：新增一個單元只需要 3 類檔案——`data/<單元>.js`、`activities/<互動>.js`、`data/tags.js` 的標籤——加上在 `data/index.js` 登記。**但 Phase B 有 5 處寫死「太陽單元」，已改為由資料驅動。**

## 發現並修正的寫死項目
| # | 位置 | 問題 | 修正 |
|---|---|---|---|
| 1 | `achievement.js` | 徽章規則寫死 `sun-shadow`、`seasons`…等實驗代號 | 改為單元資料的 `achievements[].rule`：`{lab}`／`{test}`／`{clear}` |
| 2 | `app.js` | 單元標題寫死「五年級自然」 | 由 `grade`／`subject`／`unitNo` 組成 |
| 3 | `app.js` | 節點名稱對照寫死 `a1~a4` 的太陽單元名稱 | 啟動時由原教材節點讀取 |
| 4 | `app.js` | 通關訊息、下一單元建議寫死「太陽的祕密」「植物」 | 改用資料的 `landmark`、`next` |
| 5 | `unit.html`、`science/index.html` | 備援連結、說明文字寫死五年級自然 | 改為通用連結／文字 |

## 新增
- `data/g6-u1.js`：30 題（基礎／進階／精熟各 10）、18 個知識標籤、2 個實驗、4 步老師示範、4 個徽章。
- `activities/thermal-expansion.js`（熱脹冷縮＋粒子示意）、`activities/heat-transfer.js`（傳導／對流／輻射）。
- `validate.html`：資料檢查頁（欄位、題目 id、答案索引、標籤是否定義、標籤補救入口、原教材節點是否存在、互動檔能否載入、成就規則、審核狀態）。已用故意破壞的資料驗證它確實會失敗並指出原因。
- `adventure/data.js`：六年級自然資訊卡新增「互動教材」入口。

## 測試結果
| 項目 | 結果 |
|---|---|
| g6-u1 七步流程 | 通過：6/6 星、4 個徽章、地標點亮 |
| g5-u1 在通用化之後 | 通過：5 個徽章、通關、下一步建議正確 |
| 兩單元紀錄並存 | 通過：同一個 `adv-sci-v1` 內各自的 units，互不影響 |

| 輻射模擬 | 黑杯 > 白杯；撐傘後升溫明顯降低 |
| 對流模擬 | 熱的（紅）與冷的（藍）循環 |

| 受保護檔案回歸 | 93 個檔案無異動、1479 題、自然科 309 題來源行相同 |
| 原頁面 | `island-g6-nat.html`、`island.html`、`index.html`、PDF 皆 200 |
| 手機尺寸 | 無橫向捲動 |

## 測試中發現並修掉的問題
- `heat-transfer.js` 有括號錯誤，載入失敗；系統顯示了「這個實驗暫時無法載入」而不是整頁空白。已修正，並讓資料檢查頁會實際載入互動檔以抓到這類錯誤。
- 銅球通過銅環的臨界溫度與「常溫」文字不一致，已統一（22～28°C 視為常溫，剛好通過）。

## 尚未完成／限制
- 六年級第 1 單元原本規劃 5 個實驗，目前只做 2 個（熱脹冷縮、熱的傳播）。**保溫材料效果模擬**與**水在 4°C 附近的體積變化示意**尚未做。
- 所有新增題目與說明仍為「待審核」，尚未人工確認。模擬的數值是相對示意，不是真實量測。
- 沒有真機測試；動畫在背景頁面不會自動播放，我用 `advance()` 測試鉤子驗證了模型邏輯，沒有逐幀看畫面。
- 驗證只用了兩個自然科單元；要到植物（Phase D）才會測到「圖片與辨識類」互動是否適合現有架構。
